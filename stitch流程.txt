Stitch 设计稿流程（新版 v2，2026-08-30 定稿）
========================================
已同步写入 C:\Users\qqzha\.codex\AGENTS.md（AI 全局指令），新会话自动生效。

0. 【设计前】先建议并使用 ui-ux-pro-max skill（search.py 查设计系统/落地页结构/表单UX等），
   把结论结合用户已确认的主题约束转译成 stitch 生成prompt；
   skill推荐与用户明确要求冲突时以用户为准（如已定亮色蓝主题则不采纳其暗色方案）。
1. 【建项目】create_project 后取 projects/<id中的数字作项目id。
2. 【生成/改稿】generate_screen_from_text 生成（多页逐屏生成），响应内已含状态与下载链接，
   COMPLETE 即可下载；改稿用 edit_screens，会生成新屏幕（旧屏保留），存入 v<N+1新目录；
   用户说"出v2/v3"按其版本号建目录，改哪说哪（指定某屏只传该屏id，说全部屏幕才全改）。
3. 【下载保存】每屏用响应内链接同批下载到 stitch-designs/<项目id>-v<N>/：
   - screenshot.downloadUrl 末尾加 =s0 才是原图（否则仅约512px缩略图），存为 01-页面名.png
   - htmlCode.downloadUrl 存为同名 .html（临时签名链接会过期，须与PNG同批下；纯图片屏无此链接则跳过）
   - 链接缺失用 get_screen 按屏幕id直查补拿，勿依赖 list_screens
     （索引延迟约3分钟且改稿后长时间只返回旧屏；仅多页汇总时用它并按id核对）
4. 【屏幕清单】每屏下载后记下屏幕id（响应输出可能截断，id在screens[0].id），
   并在该v目录维护 屏幕清单.md：记录 屏幕id↔页面名↔是否现行版，改稿产生新id后同步更新；
   跨会话/多屏项目靠它区分新旧版本。
5. 【预览迭代】对话中用 Markdown 绝对路径展示 PNG；要改则按第2条继续 edit_screens 出新版。
6. 【定稿交付】客户定稿（用户说"定稿/final"）：把定稿v目录的 PNG+HTML 复制到
   stitch-designs/<项目id>-final/，生成 index.html 预览页串起所有页面（本地可直接打开浏览），
   供打包发客户；正式交付用已存 HTML（Tailwind CDN 版，上线时编译为独立CSS）。

========================================
对话演练剧本（4轮话术，对应新流程）
========================================

【第1轮：立项出稿】
帮我设计一个个人开发接单的网站，工作室名称"庄生工作室"，包含多个页面：
首页（含服务内容、服务流程、咨询表单）、案例展示、关于我们。亮色主题，蓝色为主色。出好设计稿给我看。

会发生什么：先跑 ui-ux-pro-max 出设计标准 → Stitch 新建项目 → 逐屏生成 →
存 stitch-designs/<项目id>-v1/（PNG+HTML+屏幕清单.md）→ 对话里贴出全部设计稿预览。

【第2轮：提修改意见】
客户看了觉得整体可以，但主色改成粉色为主，其他保持不变，改完出 v2。

会发生什么：edit_screens 全部屏幕改主题色 → 重新导出 → 存 stitch-designs/<项目id>-v2/ →
展示粉色版设计稿（v1 蓝色版保留在原目录，随时可回滚）。

【第3轮：小细节修改（可选，模拟真实拉扯）】
第 1 屏的咨询表单下面加一句"24小时内回复"的承诺文案，其他不动，出 v3。

会发生什么：只动那一屏（只传该屏id）→ 存 stitch-designs/<项目id>-v3/。
真实客户"改一点再看一遍"的循环，想演几轮演几轮。

【第4轮：定稿交付】
客户定稿了，就用 v3。把定稿的完整设计稿和 HTML 整理到一个 final 目录，
我下载发给客户，顺便把 HTML 部署成能直接打开预览的页面。

会发生什么：复制 v3 的 PNG+HTML 到 stitch-designs/<项目id>-final/，
生成 index.html 预览页串起所有屏幕 → 打包发客户，或直接本地打开浏览。

========================================
三个使用要点
========================================
| 要点 | 说明 |
| 说版本号 | 改稿时提"出 v2/v3"，目录分版不覆盖，反悔随时回滚 |
| 改哪说哪 | "只改第1屏"比"全改"省生成时间；整站换色这种就说"全部屏幕" |
| 定稿说"final" | 触发整理+打包动作，避免散落各版本目录 |

========================================
实测要点备忘（2026-08-30 验证）
========================================
- generate/edit 响应内自带 PNG+HTML 下载链接，直接用，不必先跑 list_screens
- edit_screens 生成新屏幕不删旧屏，项目内屏幕数会持续累积，交付只取清单里标"现行版"的
- 新屏入 list_screens 索引约需 3 分钟，PNG 不受影响（响应链接即时可用）
- =s0 参数实测有效：2560px 宽原图 vs 不加时约 512px 缩略图
- 设计稿层面 aria 无障碍属性 stitch 不生成，写代码交付时需补齐
- ui-ux-pro-max 的 --design-system 可能推荐与已定主题冲突的风格（如暗色），只取兼容规范
